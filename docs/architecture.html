Vytals — Real-Time Vital Risk Scoring

Kafka → Spark Structured Streaming → HDFS lake + Postgres serving → FastAPI → Next.js dashboard. Every box below is a real module in the repo and a real service in docker-compose.yml.

Sources

Vital-sign datasets

  • data/vitals.csv — synthetic ICU series (12 patients, 4 h)
  • PhysioNet/CinC 2012 — 4 000 real ICU stays (ODC-BY)
  • HLT-009 — 25 synthetic episodes, NEWS2/qSOFA labels (CC-BY-NC-4.0)
scripts/import_physionet2012.py · import_hlt009.py
→
Ingest

Producer

vytals.ingest.producer
  • key = patient_id (per-patient ordering)
  • acks=all, retries, fail-fast if Kafka down
  • --speed 60 (60× wall clock), --loop --shift-loop
→
Buffer

Kafka topic vitals.raw

  • 3 partitions (kafka-init), replication 1

cp-kafka 7.5.0
→
Spark standalone cluster — master :7077 / :8080 · worker :8081
Query A · bronze

Validated raw vitals

  • parse → validate → event-time + watermark 2 min
  • dedupe (patient_id, event_time, seq)
  • append parquet, partition by event_date
Query B · scoring

Windowed risk scoring

  • window 5 min / slide 1 min, per patient
  • build_features() (shared with training)
  • XGBoost → p_risk, risk_score 0–100, LOW/MODERATE/HIGH/CRITICAL
  • append mode → each window scored once
Driver · vytals.streaming.job

foreachBatch on the driver

Loads the model once, scores each closed window, fans out to both sinks. Checkpoints live on HDFS, so a container restart resumes the stream.
→
